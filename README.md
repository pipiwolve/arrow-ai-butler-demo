# 箭牌智家 AI 助手 · DuMate Agent API 演示

对着箭牌《智家AI 智能助手 需求说明书》和《IoT 三方云对接接口文档》做的可运行 demo。
参考 `DumateApi接入/demo`（联想懂的「连接运营助手」）的形态，换成一个卫浴 AI 客服场景。

一句话说清它和「套壳聊天」的区别：

```
用户 → DuMate Agent（听懂意图，输出结构化动作）→ 安全闸门 → 箭牌 IoT 网关 → 审计留痕
```

模型不直连设备。它只说「想做什么」，能不能下发由本地编排层决定。这条链路正对需求 FR-07 与 3.4。

## 界面

五个视图，左侧导航切换。

| 视图 | 内容 |
| --- | --- |
| 对话 | 多轮问答。一屏三层：执行过程（Agent 干了什么）、安全闸门卡（能不能下发）、正文（结论） |
| 家庭设备 | 设备在线状态，走 IoT 网关真实接口，五列：房间 / 设备名 / deviceName / 品类 / 状态。两份清单都是 11 台。下面是已创建的场景，读审计流水（平台没有场景查询接口） |
| 安全审计 | 每一次控制与场景操作的操作人、时间、设备、动作、风险等级、决策、结果 |
| 技能管理 | 本场景 Agent 挂了哪些技能，以及整个租户技能库的搜索 / 新建 / 更新 / 删除 / 挂载 / 摘除 |
| 产物中心 | 跨会话汇总的生成物清单，点一下取平台的临时下载地址 |

对话页里会出现五种卡，对应五种去向：

- **安全闸门卡**：左侧色条按等级取色。`M` 放行、`H` 弹「确认执行 / 取消」、`C` 直接拒绝、`X` 静态校验未过
- **执行结果卡**：把真实的 HTTP 请求报文与网关响应铺出来，带耗时
- **报修卡**：只给 deeplink，卡片上写明「工单闭环不在本助手范围内」（FR-05 的范围边界）
- **产物卡**：Agent 这一轮导出的文件（如「主卫设备状态一览.xlsx」），带下载与预览入口
- **执行过程面板**：跑的时候展开，跑完折成一行。连续同类操作合并，原始入参挂在行右侧悬停显示

两个新视图动的是**真实平台资源**：技能库里那 99 个技能、以及挂给本场景 Agent 的技能，
都是客户租户上的实际对象，不是本地演示数据。删除技能按两下才算确认，挂载改动会调
`POST /agents/{id}` 并写回 `state.json`。技能增删不进 `audit.jsonl`——那条流水只记设备与场景操作。

输入框两种用法：打字，或按住麦克风说话。转写结果回填输入框，不自动发送。
长按期间**输入栏自己会动**：边框转红、左侧一个红点、一条随真实音量起伏的电平条、右侧走秒。
反馈不放在右上角状态栏——长按时人的视线在输入框上，那儿太远看不见。

## 语音输入怎么接的

**DuMate Agent API 没有语音入口。** 两套接入方式都查过：`user.message` 的 `content[]` 只认
`type: text` 与 `type: file`，没有音频 part；音频在平台里只作为**输出**产物存在
（Artifact 的 `fileType` 里有 audio）。所以语音输入进不来，只能在 Agent API 外面接一层。

demo 接的是**百度短语音识别极速版**（`src/asr-client.mjs`）：

```
按住麦克风 → 浏览器采 16k 单声道 PCM → POST /api/asr → vop.baidu.com/pro_api → 文本回填输入框
```

几处刻意的选择：

- **转写只回填，不自动发送。** 识别可能差一两个字，让人先看一眼再发；也让语音和打字汇进
  同一条后续路径，闸门与审计不必为语音单开分支。
- **音频不进审计。** 审计记的是对设备的控制与场景操作，语音本身不是控制动作。
- **没配 Key 时麦克风直接置灰**（`/api/config` 的 `voice.enabled`），不是按下去才报错；
  文字对话与整套演示不受影响。
- **浏览器侧采原始 PCM，服务端不转码。** MediaRecorder 出的是 webm/opus，百度不认，
  要转就得在服务端装 ffmpeg，那会破坏「无第三方依赖」这条。改成把 `AudioContext` 定在
  16000 Hz、用 `AudioWorklet` 抓浮点采样、自己量化成 Int16 小端裸发，走文档推荐的裸 PCM 路径。

鉴权用控制台发的 IAM 新式 API Key（`bce-v3/ALTAK-.../...`）直接做 `Bearer`。文档只写了用
AppID/API Key/Secret Key 去 `oauth/2.0/token` 换 `access_token` 那条路，实测直连可用，
少一次往返，也不用存 AppID。

**这条链路对架构文档的意义**：架构文档把语音链路按「可插拔适配器」设计（§14 R-05），
两种形态对下游编排完全透明——demo 落的是**服务端那一种**（gateway 前加 ASR 适配模块），
下游只看到文本，闸门与编排一行没改。若箭牌 APP 侧已有语音能力，这层可以整体摘掉。
也印证了 Agent API 本身不提供音频入口：ASR 是百度原子能力，与 DuMate Agent API 平行。

## 安全兜底怎么落的

需求 3.4 三条要求，逐条对应到代码。

**二次确认**（`src/policy.mjs`）：`H` 级动作不执行，先落进待确认表并返回一个 `pendingId`，前端渲染确认卡。
点「确认执行」才走 `gate.claim()` 领取并下发，领取只能成功一次（`PENDING → EXECUTING → SUCCEEDED`），
5 分钟不点自动过期。点「取消」记 `REJECTED`。高危名单来自需求 3.4 点名的三类，落到真实平台上只剩一条：浴缸 `switch_water_in`（「水阀开关」）。
需求点名的另一类「热水温度上限调节」**在真实平台上没有对应指令**——官方指令集里那条 `temp_set`
实测不被平台接受（见「真实环境实测到哪一步」），整类已删除。这一条要跟箭牌确认：
是要平台补一条温度指令，还是把这一类从高危名单里去掉。
「删除场景」不在接口的动作集里（只有 `device.control` / `scene.create` / `repair.open`），
属于未授权动作类型，直接拒且不进分级。

**权限校验**：下发前校验 `homeId` 是否本会话允许的家庭、设备是否在线、指令是否在该设备能力内、参数值是否在允许集合内。
离线设备在闸门就被拦下，报文不出本机。

**审计留痕**（`src/audit.mjs`）：每次操作追加一行 JSONL 到 `audit.jsonl`，含操作人、时间、homeId、
风险等级、判定依据、决策、目标设备、真实 HTTP 请求与响应、结果、耗时。
落盘前把 `Authorization` 头替换成 `***`，审计日志是要给客户看的。

四档风险分级沿用《权限与安全基线》§5.2 的清单：

| 等级 | 判据 | demo 里的处理 |
| --- | --- | --- |
| L | 只读查询、报修跳转 | 放行 |
| M | 常规开关（官方指令集的开关类，可逆） | 放行，留审计 |
| H | 浴缸进水阀开关（`switch_water_in`） | 二次确认后下发 |
| C | 一次影响超过 3 台 | 直接拒绝，不降级成单人确认 |

基线里 `M` 级写的是「单次确认，可配置」。demo 配成免确认是为了演示节奏，改
`config/scenario.json` 的 `policy.confirmAtOrAbove` 为 `"M"` 就能让常规开关也走确认。

## 跑起来

```bash
cd 箭牌demo打通
node server.mjs
open http://localhost:8898
```

无第三方依赖，Node 22 原生能力即可。端口在 `.env` 的 `PORT` 里改，默认 8898
（8899 留给 `DumateApi接入/demo` 那个联想懂的的 demo）。

首次打开自动 bootstrap：上传知识库与设备清单、建 Agent，结果缓存进 `state.json`。
之后复用。改完 `config/scenario.json` 要重建 Agent，访问 `http://localhost:8898/api/bootstrap?force=1`。

`IOT_MODE=mock` 时服务会同时起一个本地 IoT 网关，监听 `127.0.0.1:18899`；`IOT_MODE=real` 时不起本地网关，
请求直接打到 `.env` 里的 `IOT_BASE_URL`。启动横幅会写明当前是哪种，以及两种「真实网关」组合各自的后果。

mock 网关的运行态在内存里，**重启服务会清空**。审计流水是落盘的，不受重启影响。

设备面板那张「已创建场景」表读的是审计流水，不是网关——平台的场景接口只有创建、没有查询。
所以重启后那一屏还在（审计里有），但网关那边确实已经忘了，别拿它当平台状态看。
表里 `sceneId` 取的是平台回执里的 `sceneId`，早期记录没有这个字段时回退成「本地记录 + 时刻」。
演示中途别重启。

想清干净重来：删掉 `audit.jsonl` 和 `state.json`（后者存 bootstrap 结果，删了会重建 Agent）。

语音是可选的：`.env` 里配 `ASR_API_KEY` 才启用，不配时麦克风置灰，其余功能不受影响。
Key 从百度智能云控制台「语音技术」拿（IAM 新式 API Key，形如 `bce-v3/ALTAK-.../...`），
样例见 `.env.example`。这条链路不经 DuMate，见「语音输入怎么接的」。

本地默认没有口令门。想试线上那套，加一个环境变量即可：
`ACCESS_PASSWORD=你的口令 node server.mjs`，之后 `/api/*` 都要先过口令，页面会弹输入框。
部署到 Vercel 见下一节。

## 部署到 Vercel

同一份代码既能跑本地也能上 Vercel，差别只有三处，都由环境变量决定，不用改代码：
存储后端、是否起本地网关、是否要口令。

### 步骤

1. 推到 GitHub，在 Vercel 里 Import 这个仓库。框架预设选 **Other**，不用改构建命令，
   `vercel.json` 已经写好 `outputDirectory: public` 与函数的 `maxDuration`。
2. 在 Project → Settings → Environment Variables 里配：

   | 变量 | 必填 | 说明 |
   | --- | --- | --- |
   | `DUMATE_API_KEY` | 是 | DuMate 平台 Key |
   | `DUMATE_BASE_URL` | 是 | `https://api.dumate.cn/api/v1` |
   | `IOT_MODE` | 是 | 见下方「两种真实组合」 |
   | `IOT_BASE_URL` | `real` 时必填 | `https://api-uatiot.arrowgroup.com.cn` |
   | `IOT_TOKEN` | `real` 时必填 | 箭牌给的 bearer token |
   | `IOT_FIXTURE` | 是 | `demo` 或 `real`，见下方 |
   | `ACCESS_PASSWORD` | **客户演示务必填** | 见下方「口令门」 |
   | `KV_REST_API_URL` / `KV_REST_API_TOKEN` | 建议填 | 见下方「存储」 |
   | `ASR_API_KEY` | 可选 | 不填则麦克风置灰 |

3. Storage → 建一个 KV（Upstash Redis），Connect 到本项目，它会自动注入
   `KV_REST_API_URL` 与 `KV_REST_API_TOKEN`，不用手抄。
4. 首次访问会自动 bootstrap：上传知识库、建设备清单、建 Agent。冷启动找不到
   `state.json` 时**先按名字查一遍已有 Agent**，查到就复用，不会在客户账号里攒出一堆同名的。

### 两种真实组合，先想清楚要哪种

| 组合 | 闸门用的在线态 | 演示效果 |
| --- | --- | --- |
| `IOT_MODE=real` + `IOT_FIXTURE=demo` | 演示在线态（主卫 5 台在线） | 能走完「下发 → 平台受理」，平台回 `code 500 设备离线` |
| `IOT_MODE=real` + `IOT_FIXTURE=real` | 真实在线态（11 台全离线） | 闸门在发送前就拦下，看不到平台往返 |

真实环境 11 台设备全离线，所以想让客户看到请求真的发出去了，得用第一行。
第二行更「诚实」但演示效果差：所有控制都会被闸门拦成「设备离线」。
`IOT_FIXTURE=real` 需要仓库里有 `iot/devices.real.json`，而那个文件**含真实序列号、已 gitignore**，
Vercel 上从 git 构建是拿不到的。所以线上要用第二行的话，得把清单内容塞进环境变量或另想办法，
别指望它跟着仓库上去。默认建议用第一行。

### 存储：不配 KV 会「看着正常、其实在丢」

Vercel 的函数实例即用即弃，写本地文件下一次请求就看不见了。审计留痕是需求点名的东西，
不能随实例消失，所以线上要落外部 KV。

**KV 不是「建议配」，是必须配。** 这里踩过一个坑：`BRIEF_DIR` 当初按 `process.env.VERCEL`
切到了 `tmpdir()`，但 `state.json` 与审计/卡片流水的路径仍指向仓库目录。Vercel 上仓库目录是
**只读**的，往那儿写直接 `EACCES` 抛出来，而 `audit.append` / `writeState` 外面没有 try/catch，
于是异常一路冒到请求上——`GET /api/bootstrap` 回 500，`POST /api/ask` 一个事件都不出就断。
**不是「降级运行」，是整个 demo 起不来。** 现在兜底目录也切到 `tmpdir()`，
所以不配 KV 仍能跑，代价是数据只活在本实例里、冷启动即丢，审计页与场景列表会时有时无。
但客户演示前请把 KV 配上：审计留痕是需求点名的交付项，靠兜底等于没有。

本地跑不受影响，仍是写仓库目录，行为与改动前完全一致。

### 口令门

设了 `ACCESS_PASSWORD` 之后，所有 `/api/*` 都要先过口令，页面会弹一个输入框；
口令对上了种一个 HMAC-SHA256 的 HttpOnly cookie（12 小时），HTTPS 下带 `Secure`。
静态页不挡，否则输口令的界面自己就加载不出来。
**不设就是裸的**：任何人都能用这个 demo 去下控箭牌的真实设备，客户演示环境务必设上。

`ACCESS_PASSWORD` 与 KV 那几个变量以命令行/平台环境变量为准，不会被本地 `.env` 盖掉。
这条是踩出来的：早先 `loadEnv` 只覆盖 `.env` 里声明过的键，
`ACCESS_PASSWORD=xxx node server.mjs` 被静默忽略，现象是「明明设了口令，线上还是裸的」。

### 套餐与超时

`vercel.json` 给函数写了 `maxDuration: 300`，**Hobby 套餐不接受 300**，会直接构建失败。
Hobby 上限 60 秒，Pro 配合 Fluid compute 才能到 300。用 Hobby 就把这个数字改成 60。
一轮对话（Agent 流式回答 + 可能的工具调用）通常几秒到几十秒，60 秒够演示；
真机联调偶尔会顶到边，那时再升 Pro。

### 跨境这件事，得跟客户说在前面

两个上游都在中国大陆：DuMate 与箭牌 IoT 网关解析出来都是境内 IP，而 Vercel 没有中国大陆区域。
实测链路是「客户浏览器 → Vercel（境外）→ 境内上游」，延迟比本地跑高一个量级，
且 `*.vercel.app` 域名在大陆部分网络下访问不稳定。
给客户演示前先在客户现场的网络里试一遍。要是卡得不能看，备选是换个境内托管，
或者把 demo 录成视频——代码不用动，换部署环境即可。

## 两套设备清单，别混用

设备清单决定闸门认哪些设备，也决定 Agent 手里那份《设备与指令清单》。有两份，用途不同：

| 清单 | 文件 | 内容 | 用来干什么 |
| --- | --- | --- | --- |
| 演示 | `iot/devices.json` | 11 台，与真实环境同一批；含 `room`，主卫 5 台标在线 | 演示。真实环境 11 台全离线，跑不出成功下发，所以在线态是演示覆盖 |
| 真实快照 | `iot/devices.real.json` | 11 台，只有接口真会返回的字段 | 联调与验收。没有 `room`，接口不返回房间 |

两份的设备是同一批，差别只在 `room` 与在线态。`capability` 两边都有，但都不是接口返回的，
是 `iot/fetch-devices.mjs` 从 `config/scenario.json` 的指令表按 `appliesTo` 推导出来的——
所以改了指令表，两份都要重跑一次脚本才会同步。

真实环境那份由脚本抓，别手抄：

```bash
node iot/fetch-devices.mjs     # 需要 .env 里的 IOT_BASE_URL / IOT_TOKEN 指向真实环境
```

切清单用环境变量，`.env` 里给的是默认值，命令行可以覆盖。**当前 `.env` 里是 `IOT_MODE=real`**：

```bash
node server.mjs                                  # 当前默认：真实网关 + 演示清单（见下方说明）
IOT_MODE=real IOT_FIXTURE=real node server.mjs   # 真实网关 + 真实清单
IOT_MODE=mock node server.mjs                    # 本地 mock 网关 + 演示清单，不碰箭牌环境
```

真实网关的两种组合后果完全不同，选之前先看这张表：

| 组合 | 闸门 | 请求到得了箭牌吗 | 看到什么 |
| --- | --- | --- | --- |
| `IOT_MODE=real` + `IOT_FIXTURE=demo`（当前） | 放行（演示清单把主卫 5 台标成在线） | 到得了 | 平台回 `{"success":false,"code":500,"msg":"设备离线"}` |
| `IOT_MODE=real` + `IOT_FIXTURE=real` | 下发前就拦掉 | 到不了 | 闸门回「设备离线，无法下发：…」，零请求出网 |

真实测试家庭里 11 台全离线，这是箭牌那边的现状，改不了。所以「请求真发到箭牌」和「闸门用真值判定」
这两件事只能选一个：演示用 `demo`（发得出去，代价是闸门认定的在线态是演示覆盖），
联调/验收用 `real`（判定为真，代价是什么都发不出去）。

设备面板的在线态不受这个选择影响，它一直取真实接口的返回值，所以 `demo` 组合下会出现
「面板显示离线、闸门却放行了」——这不是 bug，是两份数据源不同，台上被问到就照这句解释。

换清单会重建 Agent（`state.json` 里记了清单版本），因为模型手里那份清单必须跟着换。
两份清单共用同一个 `state.json`，所以来回切一次就各重建一次——演示前先定好用哪份，别在现场切。
当前跑的是哪套，看 `GET /api/config` 的 `iot.mode` 与 `iot.fixture`。
**侧栏原来会显示这一行，已经摘掉了**：那是给联调看的，客户面前不需要，演示时也不该让人
盯着「本地 mock」这几个字。启动横幅仍然会打印，台上看不到。

## 真实环境实测到哪一步

用箭牌测试环境（`https://api-uatiot.arrowgroup.com.cn`，homeId 933）实测过，结论如下。

**已确认：**

| 项 | 结果 |
| --- | --- |
| 鉴权头 | `Authorization: bearer <token>` + `appPlatform` + `ArrowDeviceSystemPlatform` 三个头，照文档写就能通 |
| 设备列表 | 返回 11 台，字段与文档一致（`deviceName` / `categoryCode` / `deviceTagName` / `onlineStatus`） |
| 成功响应 | `{success:true, code:200, msg:"OK", data:...}` |
| 业务失败 | HTTP **200** + `{success:false, code:500}`。**不能只看 HTTP 状态码** |
| 错误文案 | 设备离线时是 `设备离线`；参数非法、指令名不存在、能力不匹配这三种都只回 `处理失败，请稍后重试。`；`deviceName` 不在这个家庭里回 `相应设备信息不存在！` |
| token 失效 | HTTP **401**，包体是 **XML**（`<InvalidTokenException>`），不是 JSON 信封 |
| 路径 | 设备列表是 `GET /ext/v3/ai/device-list`，写成 `deviceList` 会 403 `<ForbiddenException>` |

**没做到的：** 成功下发一条指令。真实家庭 11 台设备**全部离线**，网关对离线设备直接拒、不排队，
所以任何指令都到不了设备。能验的只有「平台收不收这条指令」。

### 靠报错文案反推指令集

既然发不到设备，就换个问法：给离线设备发一条指令，看平台回什么。

- 回 `设备离线` —— 说明**指令名、参数名、取值三样都过了校验**，只是设备没上线。
- 回 `处理失败，请稍后重试。` —— 说明**没通过校验**（指令名不存在 / 参数名不对 / 取值不在集合里，
  这三种平台不区分，统一这一句）。

把官方指令集的 11 条逐条按这个办法打到真实平台，结果是：

| 官方指令 | 平台 |
| --- | --- |
| `switch_watering` 大冲 | 收 |
| `switch_night_light` 夜灯 | 收 |
| `switch_auto_closing` 自动翻盖 | 收 |
| `switch_kicking` 脚触感应 | 收 |
| `switch_auto_oiling_porcelain` 自动润瓷 | 收 |
| `switch_onoff` 开关 | 收 |
| `switch_water_in` 浴缸进水 | 收 |
| `switch_watering_small` 小冲 | **不收** |
| `gear_seat_temp` 座温档位 | **不收** |
| `switch_warm_air` 浴霸暖风 | **不收** |
| `temp_set` 浴霸温度 | **不收** |

四条不收的试过换参数名（`gear` / `val` / `switch`）与换指令名，都不行。这四条已从指令表删除，
知识库里对应的描述也改成「只能在 App 或面板上操作」。

**校验是认设备能力的，不是全局的。** 同一条指令发给不同品类，结果是分开的：
把马桶的 `switch_night_light` 发给浴缸会被拒，反之亦然。唯一的例外是 `switch_onoff`，
它三个品类全收。

**官方说明页跟部署环境对不上。** 那份 Apifox 文档的状态是 `x-apifox-status: developing`，
它那张指令表里 11 条有 4 条在 UAT 上不存在。另外两处口径也偏窄，实测按平台放开：

| 项 | 官方说明页 | 平台实测 |
| --- | --- | --- |
| `switch_night_light` 适用品类 | 只写 `01` 马桶 | `01` 马桶与 `06` 镜柜都收 |
| `switch_onoff` 适用品类 | 挂在 `03` 毛巾架下 | `01` / `04` / `06` 三个品类全收 |

**还有一处文档与实况不符：** 接口文档「GET 设备列表」的样例返回 14 台、其中 1 台在线、含一台浴霸
（`categoryCode` `02`）。真实家庭只有 11 台、全部离线、**没有浴霸也没有毛巾架**。
这一条已经不需要再问箭牌了——样例是文档没更新的旧数据，真实家庭以接口返回为准，
演示清单现在就跟接口返回走，只是把主卫 5 台改标在线好演示成功下发。

### 这两条结论对方案的影响

跟客户讲的时候要摆出来：

1. **网关不排队。** 发给离线设备的指令直接被拒，不是存下来等上线再执行。这是好事，
   但也意味着「离线时先记下，上线后补发」这种需求得在编排层另做，网关不管。
2. **参数级报错只能由闸门给。** 参数非法时网关只回「处理失败，请稍后重试。」，
   不说是哪个字段错了。用户能看到的「参数值非法：switch=open，可选 on/off」
   这句是闸门在校验阶段给出的，网关给不了。这是闸门不可省的最直接理由。

## 用到的 DuMate Agent API 能力

| 能力 | 在 demo 里的体现 |
| --- | --- |
| File 挂载 | 知识库 md 与设备清单 json 作为 Agent 长期知识文件 |
| Skill 挂载 | `config/scenario.json` 的 `agent.skills` 按**名字**点名（如 `xlsx`），bootstrap 时在技能库里解析成 `{skillID, releaseID}`；技能管理页改挂载走 `POST /agents/{id}` |
| 改 Agent | `POST /agents/{id}` 带 `version` 乐观锁，只带变动的字段（`system` / `skills`）。`agentId` 不变，历史会话跟着保留 |
| Session + SSE | 每次提问建一个会话，全过程流式回传；追问复用同一会话 |
| 会话历史 | `GET /sessions/{id}/events` 拉完整历史，关掉页面再打开能接着看。闸门与执行卡不在平台消息里，由本层另存在 `cards.jsonl`，与历史一并返回 |
| 删除会话 | `DELETE /sessions/{session_id}` 删会话元数据及沙箱。侧栏「删除」按两下确认后走 `DELETE /api/sessions/:id`，同时清掉该会话的卡片流水。审计流水不删 |
| 产物 | `file_export` 工具 part 给出本轮导出的文件；跨会话汇总走 `GET /sessions/{id}/artifact/path-map`（不传 `path` 返回该会话全部产物，带临时签名地址） |
| 建 Agent | 人设与口径写在 `config/scenario.json` 的 `agent.system`（上限 1000 字符） |

**表里没有语音输入，因为 Agent API 不提供这个入口。** `user.message` 的 `content[]` 只认
`text` 与 `file`，音频只作为输出产物存在。语音是在 API 外面接的，见「语音输入怎么接的」。

出文件这条路要三件事凑齐才通：Agent 挂了 `xlsx` 这类会写文件的技能、system prompt 里说清
「要可下载的东西就生成真实文件」、以及这一轮真的走了 `file_export`。缺一样就只剩对话里的表格。

MCP 这一层没用上。真实对接的下一步与联想懂的 demo 一样：
把箭牌 IoT 包成 MCP Server，凭证走 Vault 挂进 Session，沙箱出站策略在 Credential 里配 `networking.allowedHosts`。
现在的做法是本地编排层代跑，好处是闸门与审计留在自己这一侧，坏处是比 MCP 多一跳。

## 数据来源与待确认项

设备名、品类编码、鉴权头、响应包体结构全部照抄客户资料，指令集以真实平台实测为准：

- 两份清单里 11 台设备的 `deviceName` / `categoryCode` / `deviceTagName` / `onlineStatus`
  取自真实环境「GET 设备列表」返回，不是文档样例
- 品类表（`01` 马桶 / `02` 浴霸 / `03` 毛巾架 / `04` 浴缸）取自客户 Apifox 在线文档的「说明」页
- 指令表 7 条，逐条打到真实平台验证过（见「真实环境实测到哪一步」）。官方说明页那 11 条里有 4 条
  平台不接受，已删除；另有两处适用品类按平台实测放开
- `time` 字段的定时语义取自「POST 场景创建」的参数说明
- 真实清单 `iot/devices.real.json` 是从真实环境抓的，接口返回的字段一个没改；
  只有 `capability` 是脚本从指令表按 `appliesTo` 推导后加上的（接口不返回能力集）

**注意 `iot接口文档/` 里那五份 markdown 是残缺副本。** 五个文件的正文完全相同（md5 一致），
是从同一份 OpenAPI 转出来的，而且**整页缺了「说明」页**——品类表和指令集都在那一页上。
只照那五个文件做，会以为接口没有指令集，然后自己编一套（这个坑真实踩过，见下）。

以下是为了让 demo 能跑而补的，客户看到时应当明说：

| 补的东西 | 为什么补 | 待谁确认 |
| --- | --- | --- |
| 设备的 `room` 字段（仅演示清单） | 「主卫那台马桶」这类说法要消歧，接口只返回 `deviceName`，没有房间 | 箭牌 APP 侧的房间模型 |
| 演示清单的 `onlineStatus` | 真实家庭 11 台全离线，照原样演示不出成功下发。演示清单因此把主卫 5 台标在线 | 无需确认，仅演示；真实清单不做这个覆盖，离线拦截照样能复现 |
| 「每天晚上」这类周期场景 | 接口文档里 `time` 是**单个时刻**（`YYYY-MM-DD HH:mm:ss`），没有周期字段，「每天晚上 10 点」按最近一次时刻下发，Agent 会在回答里说明只支持单次 | 箭牌确认是否支持周期，或由 APP 侧做重复 |
| deeplink `arrowhome://repair/...` | FR-05 要求 APP 内跳转，真实 scheme 未知 | 箭牌 APP 团队 |
| 知识库全文 | 需求 3.3 写明内容由箭牌提供 | 箭牌提供文档清单与正文 |
| 批量阈值 3 台 | 基线 §7.2 说本期直接拒绝批量，阈值未定 | 产品确认 |
| 品类编码 `06` | 官方品类表只定义到 04，真实环境却有 06 的镜柜，且平台实测收它的指令 | 箭牌补品类表 |
| 需求 3.4 的「热水温度上限调节」 | 平台上没有对应指令（`temp_set` 实测不被接受），这一类高危现在无指令可挂 | 箭牌：是补一条温度指令，还是从高危名单里去掉 |

品类表拿到后，之前从 `deviceTagName` 反推的那版编码含义已经删掉，现在是客户口径。
但官方品类表**只定义到 04**，真实环境里却有 `06` 的设备（镜柜），而且平台实测收镜柜的夜灯与开关指令。
所以 `06` 按平台放开：清单里显示成「镜柜」（名字取自设备自己的 `deviceTagName`，不是反推的），
`capability` 是 `switch_night_light` 与 `switch_onoff`。品类表缺 `06` 这一条要请箭牌补。

**`02` 浴霸与 `03` 毛巾架两个品类一台设备都没有。** 官方品类表定义了它们，指令集里也挂着对应的指令，
但真实环境只有 `01`/`04`/`06`，这两类的设备在平台上不存在，对应指令实测也都不被接受。
所以是整类删除，不是漏了。`switch_onoff` 原本挂在 `03` 毛巾架下，实测 `01`/`04`/`06` 三个品类全收，
现在按通用开关处理。

## 踩过的点

文档没写、实测才知道的。多数与 `DumateApi接入/demo` 那份记录重合，这里只记这次新遇到的：

1. **回复正文里不能留结构化 JSON。** Agent 被要求把动作块附在回答末尾，直接渲染出来是一坨 JSON。
   服务端在 `demo.answer` 事件里回一份摘掉代码块的正文覆盖显示，前端 `stripAction()` 再兜一道，
   历史回放走的是平台原文，也必须过 `stripAction()`。
2. **闸门与执行不在平台消息里，卡片要自己存。** 「闸门判定 → 下发 → 结果」和报修 deeplink
   都是本编排层的事件，平台历史里没有这三段。一开始只往浏览器推一次，回看历史时那几张卡就没了，
   只剩 Agent 正文。现在 `src/journal.mjs` 在每轮收尾时把它们落进 `cards.jsonl`，
   挂在这一轮**最后一条 assistant 消息 ID** 上；回放时平台历史里能找到同一个 ID，据此贴回各自的轮次。
   不用时间戳对齐——本地时钟和平台时钟不同源，猜不准。
   二次确认卡在回放里是终态（已确认／已取消）且不给按钮：pendingId 只有 5 分钟有效，
   现在点也只会报失效。用户当时点没点，由 `/api/confirm` 另记一条 resolve，回放时据此补出确认后才有的执行卡。
   与审计仍是两件事：审计只记真实发生的设备与场景操作（`/api/gate/simulate` 刻意不写），
   卡片流水只是回放用的界面状态，两者判据不同，所以分文件存。
   改造前建的会话没有流水，回放时依旧只有正文——这不是 bug。
3. **停在待确认的那一轮不算跑完。** 服务端 `runTurn` 拿到 `idle` 就结束了，但业务上还在等人点确认。
   `demo.done` 带上 `pendingId`，前端据此把状态栏显示成「等待确认」而不是「已完成」。
4. **`code` 为 200 也可能是业务失败。** 文档写「200 或者 10000 成功」，实测控制接口在参数非法时
   返回 HTTP 200 且 `success: false`。只看 HTTP 状态码会把失败当成功，`iot-client.mjs` 两个都判。
5. **审计里的 `Authorization` 必须先抹掉再落盘。** 网关请求头是原样带过去的，`audit.mjs` 的 `redact()`
   递归处理，字符串里的 `bearer xxx` 也一起替换。
6. **抹了落盘，忘了出口。** 这条踩了两次，第二次才发现出口不止一个。
   第一次：`audit.jsonl` 和 `cards.jsonl` 走 `redact()` 都是 `***`，但 `/api/confirm` 是
   `sendJson(res, 200, out)` 直接把执行结果回给浏览器——同一个 `out` 对象，漏抹就会让客户
   在自己的 Network 面板里看见自家 token 的明文。
   第二次：修完 `/api/confirm` 之后，`gate-auto` 那条路（`M` 级自动执行，不走确认接口）
   仍然把执行卡直接推给浏览器，`demo.exec` 事件里的 `Authorization` 还是明文。
   **根因是「出口」这个概念没数全**：一个执行结果有四个出口——审计落盘、卡片流水落盘、
   确认接口的 HTTP 响应、SSE 实时推送。前两个走 `journal.write` / `audit.append` 抹了，
   后两个各修一次才补上。现在 SSE 那侧在 `card()` 里统一抹，四个出口共用同一份已抹除的副本。
   新增出口时先想这一步。
7. **模型会把 `value` 猜成 `"1"`。** 一开始只给模型挂了设备清单（含 `capability` 指令名），
   它看到开关类指令就把值写成 `1`，闸门按 `on/off` 拒掉，现象是「设备面板看得见指令、一发就报参数非法」。
   根因是清单只说有哪些指令、没说允许哪些值。现在 `src/agent-brief.mjs` 从闸门用的同一份配置
   生成清单（含每个参数的允许取值），单一事实来源，两边不会漂移。
8. **定时场景不是独立计时器。** 模型把 `conditionList` 写成 `[{"time":"..."}]`，闸门拒了，理由却是
   「设备不在该家庭：undefined」——因为它照设备指令的规则去校验，而条件里没有 `deviceName`。
   翻文档才确认：`time` 是挂在**一条完整设备指令**上的可选字段，四个字段照样必填。
   修了两处：清单里把条件元素的形状写明白，闸门的 `inspect()` 先报「缺少哪个字段」再谈别的，
   并把错误分成「场景触发条件」与「场景执行动作」两类。
9. **Agent 会为消歧停下来，这是对的，但演示脚本得跟着改。** 「把主卫坐便器的大冲打开」
   会被反问「主卫有两台坐便器，哪一台」——主卫确实有两台在线坐便器（AKB1332-P 与 AKB1357）。
   最早的演示脚本把这一步当成一次性动作，现场会卡住。现在脚本把它当成独立的一拍：
   先让它反问，用户答「AKB1332-P 那台」，再出结果。消歧从意外变成演示点。
   **实测这一轮模型不会顺手把动作也发出来**——反问就是终态，这是对的，
   但推荐问按下去看着像「没干活」，演示前先自己跑一遍心里有数。
10. **401 返回的是 XML，不是 JSON 信封。** token 写错时网关回
   `<InvalidTokenException><error>invalid_token</error></InvalidTokenException>`，
   直接 `JSON.parse` 会抛，界面上只剩「HTTP 401」加一段 XML，看不出是 token 的问题。
   `iot-client.mjs` 现在特判 401/403，明确说「token 无效或已过期」。
11. **业务失败的 `code` 是 500，不是 200 或 10000。** 文档只说「200 或者 10000 成功」，
    没说失败是什么。实测失败一律 `code: 500` + `success: false`，HTTP 状态码还是 200。
12. **参数级报错只能自己给。** 参数非法、指令名不存在、能力不匹配这三种，网关回的都是同一句
    「处理失败，请稍后重试。」，不说是哪个字段错了。只有「设备离线」有专门文案。
    所以「参数值非法：switch=open，可选 on/off」这种提示只能由闸门出。
13. **靠报错文案反推指令集。** 真实环境 11 台全离线，成功下发验证不了，但「设备离线」这句
    本身就说明指令过了校验。拿它当探针，逐条打官方指令集，才查出 4 条平台根本不认
    （见「真实环境实测到哪一步」）。**离线不全是坏事**——它把「平台收不收这条指令」和
    「设备执行没执行」两件事分开了，前者反而更好验。
14. **网关不排队离线指令。** 发往离线设备的指令直接拒（`msg: "设备离线"`），不存下来等上线补发。
    mock 一开始漏了这条校验会照单全收，导致「mock 上过了、真实环境报错」，
    已按实测行为给 mock 补上同样的拒绝。
15. **`.env` 会盖掉命令行环境变量。** 读 `.env` 的实现如果无条件覆盖，`IOT_MODE=real node server.mjs`
    会被文件里的 `IOT_MODE=mock` 悄悄改回去，现象是「明明指定了真实环境，日志却写着 mock」。
    现在 `src/env.mjs` 让真实环境变量优先——但只对 `.env` 里**已声明的键**做覆盖，
    所以纯开关型的 `IOT_FIXTURE`（通常不写进 `.env`）要单独先读 `process.env`，
    否则 `IOT_FIXTURE=real node server.mjs` 一样会被静默忽略。加变量时留意这条。
16. **Agent API 两套接入方式都没有音频输入。** 企业版与标准化 OpenAPI 都查过：`user.message`
    的 `content[]` 只认 `text` 与 `file`，没有音频 part；音频在平台里只作为输出产物存在。
    这个结论先于实现得出，也决定了语音只能接在 API 外面。
17. **MediaRecorder 不能直接喂百度 ASR。** 它出的是 webm/opus，百度只认 pcm/wav/amr，
    要转就得在服务端装 ffmpeg。改成浏览器侧把 `AudioContext` 定在 16000 Hz、用 `AudioWorklet`
    抓原始浮点采样、自己量化成 Int16 小端裸 PCM，服务端零依赖，也省掉百度那侧的解码。
18. **`bce-v3` 新式 API Key 可以直接做 Bearer，文档没写。** 极速版文档只描述了用
    AppID/API Key/Secret Key 去 `oauth/2.0/token` 换 `access_token`。实测控制台发的
    `bce-v3/ALTAK-.../...` 直接放进 `Authorization: Bearer` 就能用，少一次换 token 的往返，
    也不用存 AppID。拿无鉴权请求做过对照（`err_no: 3300`），确认起作用的是这个 Key。
19. **AudioWorklet 节点不接到 `destination` 就不会被拉取。** 只连
    `MediaStreamSource → worklet` 的话 `process()` 根本不被调用，现象是「录音状态正常、
    发上去的音频是空的」。接一个增益为 0 的 `GainNode` 再连 `destination`：
    节点会被拉取，又不会把麦克风回放出来。
20. **首次授权弹窗会让窗口失焦。** 所以 `window.blur` 上加了「录音中才收摊」的判断——
    无条件响应的话，用户还没点完授权，录音就被自己掐掉了。同理，授权期间松手也要收摊
    （`MIC.want` 标记）。
21. **`message.part.delta` 不带 `part.type`，补默认值会污染 part 建模。** 实测一回合里平台吐了
    6 个 `reasoning` part，其中最长的一段 741 字，而真正的正文只有 69 字；`updated` 帧带
    `part.type`，`delta` 帧只有 `partID`。delta 处理里若给缺省的 `type` 补一个 `'text'`，
    就会把 updated 早先标好的 `'reasoning'` 覆盖掉，那段思考变成候选正文——`answerId` 取最长的
    text part，741 字压过 69 字，整段思考就被当成回答渲染出来。修法是不在 delta 分支补 `type`，
    让 `upsert` 只在新建记录时默认 `text`，后续 `updated` 帧仍能纠正。
    注意：这一条是**防御性**的——实测那条流里每个 part 的末帧都是 `updated`，会把类型纠回来，
    所以当次并没有复现。但顺序不保证，别把默认值加回去。
22. **录音反馈要落在输入栏里，不能只放右上角。** 长按时视线在输入框上，右上角那行状态字
    再准也看不见。现在边框转红 + 红点 + 电平条 + 走秒都在输入栏内，右上角只留一个静态的
    「录音中」，免得状态区谎报「空闲」。松手后的失败原因同样在输入栏闪一下（右上角同时留一份
    持久状态）——`micFlash` 之后 `finally` 里不能再调 `micPaint('')`，那会把刚写上的错误文字擦掉。
23. **电平条要取真实采样，映射窗口还得调。** 它由 worklet 每 8ms 推来的 128 采样算 RMS
    （逐块画太密，125 次/秒，所以只累积峰值交给 rAF 按帧取走），不是装饰动画——这样它顺带
    回答「麦克风到底有没有收到声音」，演示前按一下就知道麦是不是被静音了。
    映射窗口是试出来的：RMS 直接线性画、或按 -60~0dB 画，正常说话都会挤在顶部，看着像一块
    实心色块；取 **-52~-10dB** 这段，正常说话的 RMS（0.01~0.1，即 -40~-20dB）正好落在中部，
    起伏才看得出来。回落用 `shown*0.72 + lv*0.28` 缓释，柱子不会一闪一闪。
24. **`POST /agents/{id}` 的 `version` 是乐观锁，数组字段是全量替换。** 不带 `version` 直接报错；
    `skills` / `files` / `mcpServers` 都是整组替换，只想加挂一个技能也得把现有的全带上。
    所以 bootstrap 不能每次重建 Agent——那样 `agentId` 会变、历史会话全丢。现在改成：
    比出差异再带 `version` 调一次更新，`agentId` 保持不变。
25. **改提示词要进复用判断，不然会静默不生效。** 早先的 bootstrap 只比挂载文件和技能，
    改了 `config/scenario.json` 的 `agent.system` 不会推上去，现象是「配置明明改了，回答还是老口径」。
    现在 `state.json` 里存提示词的 sha1 前 12 位（`promptKey`），启动时比一次，不一致才推。
26. **`GET /agents/{id}` 不返回技能名，也不返回文件名。** `skills` 只有 `{skillID, releaseID}`，
    `files[]` 只有 `fileID`。界面上「已挂 xlsx」这种可读的名字是编排层补的：
    技能回技能库按 ID 查，文件名回 `state.json` 按 `fileID` 取。
27. **`GET /skills` 的 `page` 与 `pageSize` 都必填，搜索参数叫 `keyword`。** 写成 `name` 或
    `search` 不报错，只是当没传——不生效比报错难查。列表项也不返回 `builtin`（只有详情才有），
    判内置要用 `createBy` 是否以 `system:` 开头。
28. **建技能与更新技能收的东西不一样。** `POST /skills` 只收 JSON `{url}`（GitHub / ClawHub / BOS），
    不收包；传 ZIP 只存在于 `POST /skills/{id}/update` 的 multipart `file` 字段里。
    界面上的「新建」因此只能填地址，传包挂在每一行的「更新」下面。
29. **产物没有列表接口，但会话级的 `path-map` 就是。** `GET /sessions/{id}/artifact/path-map`
    返回**以沙箱绝对路径为键的 map**，值里有 `downloadUrl` / `previewUrl` / `pdfUrl` /
    `mimeType` / `size` / `uploadStatus`。`path` 收绝对路径或裸文件名，`ses_xxx/文件名`
    这种相对形式返回空。**不传 `path` 时返回该会话的全部产物**——最早在没产物的会话上试，
    拿到 `{}`，误判成「必须传 path」，换了真有产物的会话才看清。
    沙箱里刚写好的文件在平台侧登记是异步的，所以一轮收尾要轮询几次才拿得到下载地址。
    `/sessions/{id}/artifacts`、`/sessions/{id}/files`、`/artifacts?sessionId=` 都是 404。
30. **跨会话清单没有「产物时间」可用。** `path-map` 不带产物自身的时间，只能拿会话的更新时间
    当序，界面上那一列因此写的是「会话时间」。会话内那张产物卡的时间来自 `file_export`
    这个 tool part 的 `state.time.end`，两边取的不是同一个东西。
31. **平台报的 `size` 别当校验值。** 同一个 xlsx，`path-map` 报 6254 字节，下载下来是 27992——
    平台重新打包过一次（里面的条目是 store 方式）。界面上按平台给的原样显示，不当「文件大小」用。
32. **客户给的五份接口文档是残缺副本，指令集得去在线文档拿。** `iot接口文档/` 里五个 md
    正文完全相同（md5 一致），是从同一份 OpenAPI 转出来的，**整页缺了「说明」页**——
    品类表（`01`–`04`）和指令集都在那一页上，接口定义那一侧一条指令都没有。
    只照这五个文件做，会得出「接口没有指令集」的结论，然后自己编一套指令（这个坑真实踩过：
    编了 `switch` / `set_water_temp` / `set_warm_air_temp` / `switch_valve` 四条，
    还标成了 `source: "doc"`）。**发现办法**：文档页脚有原文链接，顺着找到在线文档，
    密码页过了之后每页都有 `.md` 版本，还有 `/llms.txt` 做索引，整份 OpenAPI 直接可取。
    下次客户只给导出件时，先问有没有在线地址，别急着按缺的那份实现。
33. **找到在线文档也不算完，那张指令表本身就跟部署环境对不上。** 说明页上 11 条指令，
    逐条打到真实平台，有 4 条平台不接受（小冲、座温档位、浴霸暖风、浴霸温度），
    文档状态还是 `x-apifox-status: developing`。**文档是客户写的意图，平台才是能跑的东西**，
    两者不一致时以后者为准，并把差异列成清单交回客户。
    这一轮差出四类问题：4 条指令不存在、2 处适用品类写窄了、1 条需求点名的高危指令（热水温度上限）
    在平台上没有落点、1 个品类编码（`06` 镜柜）官方表里没有。四类都在「数据来源与待确认项」里列着。
    验的办法在「真实环境实测到哪一步」——离线设备回的那句「设备离线」就是探针。
34. **演示用的补充接口会悄悄变成对外口径。** mock 网关一开始按接口文档实现三个 endpoint，
    后来为了让演示面板能立刻看到「刚下发的指令生效了」，多挂了 `GET /scene-list` 与
    `GET /demo-state`，注释里也写了「demo 补充，接口文档未提供」。但界面照常展示它们的数据，
    看的人分不出哪一列是平台的、哪一列是我们自己造的——切到真实网关时才暴露：
    一个必然 404，一个没有数据源。**mock 只该 mock 真实存在的东西**，
    要展示平台给不了的信息，就在界面上写明来源，别新开一个假 endpoint 撑着。
    现在的处理：两个都撤了，场景列表改读审计流水，设备页去掉那两列。

35. **两个存储后端对 `tail()` 的顺序不一致。** 为了上 Vercel，审计与卡片流水抽了一层
    `src/store.mjs`：本地写文件、线上写 KV。文件后端的 `tail(n)` 是
    `lines().slice(-n).reverse()`，最新在上；Redis 后端的 `LRANGE key -n -1` 出来是正序，
    最旧在上。`/api/audit` 把 `tail()` 的结果直接回给前端，所以这个差别不报错、不丢数据，
    只是**上了 Vercel 审计页会整个倒过来**，而本地怎么试都是对的。
    写这段时文件头注释还写着「两个后端的语义对齐在追加 + 倒序取尾部 + 全量取这三件事上」——
    注释声明了不变量，代码没做到。补了 `.reverse()`，并加了一条跨后端一致性断言
    （同一个键往两边各写一遍，比 `all()` 与 `tail()` 的输出），免得以后再分叉。

36. **只读盘上的写失败会一路冒到请求上。** 见上面「存储」那节。教训不是「Vercel 目录只读」
    这件事本身，而是**同一个判断只改了一半**：`BRIEF_DIR` 记得按 `VERCEL` 切到 `tmpdir()`，
    `STATE_FILE` 和审计路径忘了。半截的适配比不适配更难查——启动横幅照常打印、
    日志里那句 KV 警告照常出现，看着像「降级运行」，实际每个请求都 500。
    写这类环境适配时，把「哪些路径要写」一次列全，别按文件逐个想起来。

37. **Agent 挂载的文件会在平台上失效，而按名字复用会继续信那个失效的 fileID。**
    `bootstrap()` 只有**新建** Agent 时才上传文件（`uploadFile` 那一段在最后）；
    复用路径（state 命中、或按名字查到时）一律不重传，直接信 state 里存的 fileID。
    实测：隔了几小时再跑，同一个 Agent 的配置里两个 fileID 都还在，
    但 Agent 自己说「`files/` 和 `uploads/` 目录均为空」，于是拒绝下发指令，
    回答变成「请上传设备与指令清单」——**不报错、不进审计，看着像模型不听话**。
    强制 `?force=1` 重建（重新上传）后立刻恢复，同一句提问又能正确解析出
    「主卫 ACH102 浴缸 / `switch_water_in`」并触发 H 级闸门。
    所以这不是复用逻辑写错（用一个刚建的 Agent 走查名字复用，验过是好的），
    是平台侧的上传件过期。**影响 Vercel 部署**：state 存在 KV 里，冷启动走的就是复用路径，
    文件过期后线上会静默退化成「Agent 说它没有清单」。
    待办：要么让 bootstrap 每次都重传挂载文件再 PATCH 回 Agent（代价是每次冷启动多两次上传，
    账号里会攒无用上传件），要么在界面上给一个「重建 Agent」的按钮并写清什么时候要按。
    没定之前，**长时间没动过的环境在演示前先 `?force=1` 重建一次**。

## 演示节奏

**这一段跟的是演示清单（`IOT_FIXTURE=demo`）。** 换成 `IOT_FIXTURE=real` 后，带「主卫」的几条
失了依据，因为快照没有房间字段，Agent 只能按一样的 `deviceTagName` 反问；
而且 11 台全离线，成功下发那几张执行卡出不来。真实的推荐问要等箭牌确认房间模型后再定。

首屏七条推荐问，一条一个场景，从上往下走：

1. **「把主卫的浴缸进水打开」**：`H` 级，闸门停下弹确认卡，先不点，
   讲清「模型说想开水阀，但下发权不在模型手里」。点确认，指令才出去，执行卡出请求与响应。
   刷新页面重来一次点「取消」，走拒绝路径。约 90 秒。
   这条同时是需求 3.4 点名的「水阀开关」，也是现在唯一的高危指令
2. **「把主卫坐便器的大冲打开」**：主卫有 **2 台**在线坐便器（AKB1332-P 与 AKB1357），
   Agent 会先反问是哪一台，这一步讲「模型不猜，拿不准就停」。**实测这一轮就停在这里不再往下走**
   （答完之后才是 `M` 级放行）。消歧是演示点，不是卡壳，现场别急着补话。约 60 秒
3. **「把主卫镜柜的夜灯打开」**：`M` 级放行。这条专门用来说 `06` 镜柜——
   官方品类表里没有这个品类，平台却收它的夜灯指令，是「以实测为准」的一个例子。约 40 秒
4. **「每天晚上 10 点自动给主卫浴缸放水」**：场景创建，条件带 `time`，动作是 `switch_water_in`，
   去设备面板看场景列表（那一屏读本地审计流水，平台的场景接口只有创建没有查询）。
   这条同时会命中 `H` 级，说明高危校验对场景与单次控制一视同仁。Agent 会说明接口只支持单次定时，
   顺带把「周期场景怎么支持」这个待确认项当面抛给客户。约 60 秒
5. **「AKB1357 有哪些功能？」**：产品百科，Agent 检索挂载资料作答。
   注意知识库会答「座温 10 档」，但座温在平台上没有可下发指令，语音改不了——
   被追问时照「边界场景」那节的说法解释
6. **「我家坐便器不出水了，要报修」**：返 deeplink，卡片上写明不碰工单系统
7. **「把主卫所有设备的状态整理成一份表格」**：交付物那条线。Agent 读设备清单，调 `xlsx` 技能写出
   **真实的 .xlsx 文件**，对话里落一张产物卡，点「下载」拿到真文件。然后切到产物中心，看跨会话
   汇总出来的清单（跨会话是因为换台电脑、换个会话，产物还在平台上）。
   这一步讲的是「交付物是文件，不是对话里的表格」。**实测这一轮要跑几分钟**——现场别盯着等，
   发出去之后先切到技能管理讲别的，回来再收产物卡。

**技能管理那一页最好放在第 7 条之前看**，它解释第 7 条为什么能出文件：Agent 上挂了 `xlsx`，
所以它有本事写表格。可以搜一个 `xlsx` 给客户看技能库是租户级的、99 个技能里哪些是平台内置的。
**台上不要点删除、也不要摘挂载**——那动的是真实租户资源，摘了第 7 条就出不了文件了。

**第 1 条建议改成按着麦克风说**，这是唯一一处需要出声的演示点，放在最前面：
按住麦克风说「把主卫的浴缸进水打开」，松手后文字回填进输入框，停一下让客户看清
「转写结果在这儿，我没替你发」，再按发送。这一步同时把 FR-01 的「语音」和 FR-06 的「输入形态」
一次讲完，而且接下去正好落到二次确认卡上，链路最完整。

**演示前先按住试一下，看电平条动不动。** 麦克风没置灰只说明 Key 配好了；电平条不随说话起伏，
说明系统输入设备选错了或被静音——这个在台上才发现就来不及了。

**别把语音说成 Agent 的能力。** 它是百度 ASR 转成文字之后才进 Agent 的，与打字走同一条路。
客户若问「能不能直接对着它连续说话」：按架构文档 C5 本期就是半双工，不做全双工，
所以这不是缺项；但要说清**免提连续对话需要 VAD 打断与并行流，不在本期范围内**。

最后切到安全审计，把刚才所有操作一条条对一遍：谁、什么时候、哪台设备、什么风险等级、是否下发成功。
这一步是整场演示的收口，也是需求 3.4 第三条的验收证据。

## 边界场景怎么演示

拦截发生在两层，讲的时候要分开说，混在一起会被问住：

**模型层**（Agent 自己就停了，闸门没参与）：清单里没有的指令，system prompt 要求
「清单里没有的设备、指令或取值，直接说做不到，不要用相近的值凑」，模型会主动拒绝并说明原因。
实测「把主卫坐便器的小冲打开」得到的是「小冲没有可下发的指令」，不是拦截卡——
小冲这条指令在真实平台上不存在，已从指令表删掉。
这是好事，说明第一层就拦住了，但**别把它说成闸门的功劳**。

**闸门层**（模型输出了动作，闸门判定不下发）：批量超阈值这条走的就是闸门，
「把家里所有坐便器和浴缸的进水阀都关掉」→ 10 台设备 → `deny X`，理由写在一张灰卡上。

**两层之间还有一条缝，讲的时候值得点一下。** 大冲这条指令平台只收 `on`，没有 `off`。
知识库里写「支持大冲」，用户说「把大冲关掉」时，模型层应该拒（清单里明确写了
「只列了 `on` 的指令没有反向取值，不要自己补」）；万一模型还是输出了 `switch=off`，
闸门也会按「参数值非法：switch=off，可选 on」拒掉。两层都拦得住，但拦的理由不一样——
一个说「没有这个功能」，一个说「值不在允许集合里」。
这不是 bug，是平台指令集本身的限制，现场被问到就照实说。

想让闸门那四道检查**按需复现**（演示和联调都需要，否则要看模型心情），有一个只判定不下发的旁路：

```bash
curl -s -X POST http://127.0.0.1:8898/api/gate/simulate -H "Content-Type: application/json" \
  -d '{"action":"device.control","targets":[{"deviceName":"ARROWToilet17419421020631","cmd":"switch_watering","param":"switch","value":"off"}]}'
```

请求体就是一个动作对象，返回 `{decision, level, reasons, items, dryRun}`。
`dryRun` 意味着不建待确认记录、不写审计，所以它不会污染审计证据，也不会让 `/api/confirm` 有东西可领。
下面这些判定都能这么复现（按**演示清单**列，换 `IOT_FIXTURE=real` 后设备名与在线态都不同，
设备名要从设备面板里取）。这张表是逐条跑出来的，不是照着代码推的：

| 场景 | decision / level | 拦截理由 |
| --- | --- | --- |
| 大冲 `switch=off` | `deny` / `X` | 参数值非法：switch=off，可选 on |
| 大冲 `switch=open` | `deny` / `X` | 同上（取值只能是 `on` / `off`，不认 `open`） |
| 小冲 `switch_watering_small` | `deny` / `X` | 指令不在指令表内：switch_watering_small |
| 座温 `gear_seat_temp` | `deny` / `X` | 指令不在指令表内：gear_seat_temp |
| 镜柜夜灯带 `gear` 参数 | `deny` / `X` | 指令 switch_night_light 没有参数 gear |
| 浴缸发马桶大冲 | `deny` / `X` | ACH102智能浴缸 不支持指令 switch_watering |
| 客卫坐便器大冲 | `deny` / `X` | 设备离线，无法下发：akb162111（客卫） |
| 清单外的设备 | `deny` / `X` | 设备不在该家庭：ARROW9999999999999999 |
| 未授权动作 `device.delete` | `deny` / `X` | 未授权的动作类型：device.delete |
| 只给 `time` 的条件 | `deny` / `X` | 场景触发条件校验未过：指令项缺少 deviceName 字段 |
| 一次关 10 台水阀 | `deny` / `X` | 一次操作涉及 10 台设备，超过阈值 3 台，本期内一律拒绝 |
| 浴缸进水 `on` | `confirm` / `H` | 浴缸进水阀开关（需求 3.4 点名的「水阀开关」） |
| 定时场景里放浴缸进水 | `confirm` / `H` | 同上（高危校验对场景与单次控制一视同仁） |
| 主卫马桶大冲 `on` | `allow` / `M` | M 级操作，未达二次确认阈值，闸门放行 |
| 镜柜夜灯 `on` | `allow` / `M` | 同上 |
| 马桶 `switch_onoff=off` | `allow` / `M` | 同上（`switch_onoff` 三个品类全收） |
| 浴缸 `switch_onoff=off` | `allow` / `M` | 同上 |

`X` 是「静态校验没过」，不是一个风险等级——这个动作没资格进入分级。混进 L/M/H/C 会让审计看着像在分级。
这个旁路不写审计，审计只留真实操作的证据。
